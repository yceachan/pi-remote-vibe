# Issue 1：安卓 PWA 远程操作 PC 上的 Pi

状态：待审阅（2026-11-03）

## 目标

在安卓浏览器安装的 PWA 中，选择家中或其他地点的 PC 与 Pi 会话，提交任务并查看流式结果。手机锁屏、切后台或断网后，任务继续在 PC 上运行；重新打开 PWA 时接回同一会话。Pi 使用该 PC 当前用户的项目文件、Pi 配置、skills、扩展、工具及模型凭据。

预期部署由三个自有组件组成：安卓 PWA 提供界面和浏览器 SSH 客户端；公网 VPS 提供 Passkey 登录及 WSS 到 TCP 的字节中继；每台 PC 部署常驻会话管理服务，管理本机 Pi RPC worker。PC 主动向 VPS 建立反向 SSH 隧道，手机通过中继与 PC 的 sshd 建立另一条独立 SSH 连接。

## 首版使用场景

1. 用户用 Passkey 登录 PWA，选择已登记的 PC 和项目，创建或进入会话。
2. PWA 校验 PC 的 SSH 主机密钥，以手机本地 SSH 密钥认证，打开非 PTY 会话接入 PC 服务。
3. 用户输入 prompt，查看增量文本、工具活动及完成状态；可切换至另一个仍在工作的会话。
4. 用户锁屏或断网，PC 上的会话继续；重连后取得历史、当前状态和后续事件，避免重复提交。
5. 同一会话可在多端查看；首版同一时刻由一个客户端控制输入。

## 产品范围与验收

| 能力 | 首版可验收结果 |
|---|---|
| 多主机与项目 | VPS 仅转发到预先登记的主机；PC 列出其可用项目和会话；两台 PC 可各自独立运行。 |
| 多会话执行 | 一台 PC 上两个活跃会话各有 Pi RPC worker，可分别接收 prompt 和流式事件。 |
| Pi 交互 | 会话历史、流式文本、工具活动、停止、模型切换、skill／模板／扩展命令列表与标准扩展弹窗可在 PWA 使用。 |
| 连接与身份 | Passkey 控制中继入口；手机 SSH 密钥由 PC sshd 验证；PC 隧道密钥由 VPS sshd 验证；PWA 校验已登记的 PC 主机密钥。 |
| 手机密钥 | SSH 私钥加密保存于浏览器本地存储，解锁后仅在页面运行时内存中使用；网站登录与私钥解锁分别进行。 |
| 持续与恢复 | 手机断开期间 Pi stdout 持续被消费；重连时先建立一致状态，再接续增量事件；缓存缺口触发完整同步；同一操作重试不会造成重复 prompt。 |
| 重启后恢复 | PC 或 worker 重启后能重新载入已保存的 Pi session 历史，并明确显示中断任务的状态。 |

首版界面以会话操作为中心。文件浏览、Git diff、项目文件编辑器和动态参数补全可作为后续能力；首版输入编辑区需支持多行输入、草稿、输入历史及命令插入。附件的类型和传输方式待阶段 2 定义。对扩展，仅覆盖 Pi RPC 已暴露的标准交互。

## 边界与待审阅项

- Pi worker 是独立进程，使用既有 Pi 配置与 session 文件；接管已经运行的 Pi TUI 进程不在本 issue 中。同一 session 文件由一个活跃 worker 写入。
- 恢复已保存的对话历史是首版目标。PC 重启时已经执行的任意工具进程，按“中断并显示状态”处理；任务级断点续跑需另立需求。
- VPS 按固定主机 ID 映射回环监听端口，承载 SSH 密文字节；其登录服务负责入口鉴权和授权。PC 主机密钥仍须由 PWA 独立核验。
- 浏览器 SSH 库的非 PTY exec、双向二进制流、主机密钥验证及安卓浏览器兼容性，是路线开始前必须通过的技术关口。未通过时先审议连接方案，再扩展产品实现。
- PC 主机密钥的首次可信登记方式、首版附件范围和目标 PC 平台，是实施前需要与实际设备和使用习惯对齐的细节。

完成条件：上述首版使用场景在安卓 PWA、VPS、至少两台 PC 的目标部署中演示通过，关键操作及断线恢复有可复现的验证记录，随后为 issue 撰写 `close.md`。
